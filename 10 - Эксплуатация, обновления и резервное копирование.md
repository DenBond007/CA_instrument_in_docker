# Эксплуатация, обновления и резервное копирование

> [!important] Где выполнять команды
> В каталоге распакованного `SA-Docker-Obsidian`, где лежит `compose.yaml`. Сервисы называются **как в Compose** (`kroki`, `mermaid-editor`, `swagger-ui`, ...), не путайте с именами созданных Docker-контейнеров.

## Управление сервисами

| Задача | Команда |
|---|---|
| Все контейнеры на машине | `sudo docker ps -a` |
| Состав набора | `sudo docker compose ps` |
| Запустить / применить изменения | `sudo docker compose up -d` |
| Остановить набор без удаления | `sudo docker compose stop` |
| Запустить после Stop | `sudo docker compose start` |
| Перезапустить только Kroki | `sudo docker compose restart kroki` |
| Просмотреть логи рендеринга | `sudo docker compose logs --tail=100 -f kroki kroki-mermaid` |
| Остановить и убрать контейнеры/сеть набора | `sudo docker compose down` |
| Проверить YAML | `sudo docker compose config --quiet` |
| Посмотреть нагрузку | `sudo docker stats` |

Не используйте `docker compose down -v`, `docker system prune -a --volumes` без понимания последствий. Для Portainer состояние хранится в отдельном `portainer_data`.

## Очистка места на Ubuntu

```bash
# Только показать план, без sudo и удаления файлов:
bash scripts/cleanup-disk.sh

# Выполнить план после подтверждения; sudo запросит пароль при необходимости:
bash scripts/cleanup-disk.sh --apply

# Сначала проверить список ненужных пакетов APT:
bash scripts/cleanup-disk.sh --autoremove

# Очистка вместе с удалением показанных пакетов:
bash scripts/cleanup-disk.sh --apply --autoremove
```

Скрипт очищает установщики APT, неиспользуемый кэш сборок **локального** Docker, образы без тегов, старые ревизии Snap и неиспользуемые окружения Flatpak. Архивные журналы systemd ограничиваются 14 днями и 200 МиБ; лимит размера может удалить и более свежие архивы. Политика хранения журналов в конфигурации системы не меняется.

Пользовательские кэши ограничены pip, uv, npm, `/tmp/sopds-release-sca/trivy/cache` и папками `~/.cache/codex-runtimes/codex-runtime-install-*` без изменений за последние 7 дней. Перед удалением проверяются владелец, символические ссылки, точки монтирования (включая вложенные, через `findmnt`) и открытые файлы (через `lsof`). Занятые каталоги пропускаются; ошибка проверки отражается в итоговом коде завершения. После очистки кэши и кэш сборок будут создаваться заново.

С параметром `--autoremove` менеджер APT дополнительно запросит подтверждение по окончательному списку удаления. Это учитывает возможные изменения списка пакетов после предварительной симуляции.

Контейнеры, volumes, образы с тегами (включая образы отката), `.env`, резервные копии, файлы проектов, установленные версии Codex, `codex-primary-runtime`, swap и резерв ext4 сохраняются. Скрипт не удаляет данные приложений Flatpak. Запускайте от обычного пользователя; запуск через `sudo` также учитывает исходного пользователя.

## Обновление готовых образов

```bash
bash scripts/backup-config.sh
bash scripts/update.sh
bash scripts/healthcheck.sh
```

`update.sh` обновляет готовые образы, включая Mermaid из GHCR, и пересоздаёт контейнеры. Для новой версии Mermaid сначала измените тег `MERMAID_IMAGE` в `.env` (например, с `1.0.0` на опубликованную `1.0.1`). Пакет публичный, скачивание не требует авторизации.

Смена `BIND_IP`, `KROKI_PORT` или `KROKI_URL` не требует новой сборки: выполните `sudo docker compose up -d --no-build mermaid-editor`. Новые настройки загрузятся после обновления страницы браузера. Простого `restart` недостаточно для изменения окружения.

Сборка нового образа и обновление закреплённого upstream выполняются через GitHub Actions; см. [[03 - Mermaid и локальный Kroki]]. Предпочтительно фиксировать версии/digest образов; `latest` не гарантирует воспроизводимости.

## Резервное копирование файлов аналитика

```bash
bash scripts/backup-config.sh
```

Создаст `backup/sa-analyst-config-YYYYMMDD-HHMMSS.tar.gz` с Compose, `.env`, примерами и контрактами из `specs/`. Не включает клонированные исходники Mermaid и **не включает базу Portainer**.

Также резервируйте ваши **реальные** `.mmd`, `.puml`, `.drawio`, `.yaml` и `.md` в Git/NAS. Скрипт сохраняет только файлы внутри этого Obsidian-каталога.

## Резервная копия данных Portainer (volume)

> [!warning] Окно обслуживания
> Чтобы избежать несогласованной копии базы, Portainer следует остановить на время backup. Команды ниже предполагают **отдельную установку через `compose.portainer.yaml`**; если Portainer был установлен ранее иным способом, адаптируйте команду Stop/Start к реальному контейнеру.

```bash
mkdir -p backup
sudo docker compose -f compose.portainer.yaml stop portainer
sudo docker run --rm \
  -v portainer_data:/data:ro \
  -v "$PWD/backup:/backup" \
  alpine:latest sh -c 'cd /data && tar czf /backup/portainer_data.tgz .'
sudo docker compose -f compose.portainer.yaml start portainer
```

**Важно:** если бэкапирование прервалось после Stop, **вручную** запустите Portainer. Если приложение запущено с другим volume, `portainer_data` может быть неверным: сначала смотрите `docker inspect`.

### Восстановление

- Для файлов конфигурации: остановить соответствующие контейнеры, восстановить файлы из архива, проверить `.env`, затем `docker compose up -d`.
- Для `portainer_data`: остановить Portainer, восстановить содержимое соответствующего volume из резервной копии во временном контейнере, затем запустить. Это операция с риском перезаписи/потери данных — сделайте snapshot текущего volume и проверьте имя **до** восстановления.

## Данные каждого продукта

| Продукт | Где данные живут в этой конфигурации |
|---|---|
| Portainer | Named volume `portainer_data` — резервировать обязательно |
| Swagger UI | `specs/openapi.yaml` — bind mount, чтение |
| Mermaid Live Editor | Исходники/экспорт — сохранять на клиент/в Git; в нашей конфигурации нет volume пользовательских схем |
| PlantUML, Kroki | Преобразуют текст в картинку, сами исходные диаграммы не сохраняют в наш каталог |
| draw.io | Сохраняйте `.drawio` на устройство и в Git |
| Swagger Editor, AsyncAPI Studio | Экспортируйте YAML/JSON вручную; черновики браузера ненадёжны |

**После изменения параметров Kroki/IP** пересоздайте контейнер Mermaid без сборки, см. [[03 - Mermaid и локальный Kroki]].
