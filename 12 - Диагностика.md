# Диагностика неполадок

Все команды в этой заметке запускаются в каталоге `SA-Docker-Obsidian`, кроме явно указанных. Длинные лог-файлы собирайте отдельно, не публикуйте с секретами.

## Диагностический блок

```bash
sudo docker version
sudo docker compose version
sudo docker compose config --quiet
sudo docker compose ps
sudo docker compose logs --tail=100
sudo docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
sudo ss -lntp | grep -E ':(9443|1808[0-7])\b' || true
ip -4 -brief address
bash scripts/healthcheck.sh
```

## Таблица проблем

| Симптом | Возможная причина | Проверка/решение |
|---|---|---|
| Портал не открывается на `18080` | Образ не скачан, контейнер не запущен или другой `PORTAL_PORT` | `sudo docker compose ps portal`, `sudo docker compose logs --tail=100 portal`, проверить `http://<BIND_IP>:<PORTAL_PORT>/health` |
| Портал открывается, но ссылки ведут на старый адрес | Контейнер ещё использует старую конфигурацию | Проверить `/runtime-config.js`, выполнить `sudo docker compose up -d --no-build portal` и обновить страницу |
| Портал не запускается после изменения настроек | Некорректный host, порт, URL или флаг Portainer | `sudo docker compose logs portal`; `PORTAL_HOST` — IP/DNS без схемы, флаг — `true`/`false`, URL Kroki/Portainer — HTTP(S) без пароля/query/fragment |
| `bind: cannot assign requested address` | `BIND_IP` не принадлежит Ubuntu | `ip -4 -brief address`, исправить `.env` |
| `port is already allocated` | На порту остался старый контейнер | `sudo docker ps --format '{{.Names}} {{.Ports}}'`; остановить **нужный** старый стек либо поменять порт |
| `denied` при скачивании Mermaid из GHCR | Пакет закрытый или нет доступа | `sudo docker login ghcr.io`, classic PAT с `read:packages`, проверить доступ к пакету и `MERMAID_IMAGE` |
| Mermaid открывается, но Kroki-ссылка ведёт на `kroki.io` | Запущен официальный образ/старая сборка или кэш | `docker compose ps`, проверить `MERMAID_IMAGE`, `/runtime-config.js`, выполнить `up -d --no-build mermaid-editor`, обновить страницу |
| Mermaid → Kroki: `ERR_CONNECTION_REFUSED` | Kroki остановлен или IP/порт неверный | `sudo docker compose logs kroki`; сверить `.env`, `KROKI_URL` и `/runtime-config.js`; `healthcheck.sh` |
| `/mermaid/svg` возвращает 4xx/5xx | Ошибка диаграммы, Kroki-companion или лимит | Посмотреть `kroki` и `kroki-mermaid` логи, повторить с `samples/sequence.mmd` |
| Swagger UI не видит новый контракт | UI не перезагружен после замены файла | Проверить `specs/openapi.yaml`, `sudo docker compose restart swagger-ui` |
| Swagger Editor работает, файл сервера не меняется | Это независимый браузерный редактор | Экспортировать YAML и переписать `specs/openapi.yaml` вручную |
| draw.io перенаправляет на HTTPS или не открывается | Особенности приложения/браузера | URL с `?offline=1&https=0`; проверить лог drawio |
| Portainer не открывается | Контейнер не запущен / другой порт | `sudo docker ps -a | grep portainer`; проверить `9443` по HTTPS |
| Portainer требует setup token | Начальная настройка | `sudo docker logs <имя-portainer>` и найти токен в логах |
| `Mixed Content` при HTTPS Mermaid | Kroki доступен по HTTP | Указать HTTPS адрес в `KROKI_URL`, выполнить `up -d --no-build mermaid-editor` |
| Docker pulls заканчиваются ошибкой | Нет сети/места на диске/реестры недоступны | `sudo docker system df`, `df -h`, DNS и сетевые журналы; не удалять volumes вслепую |

## Изоляция источника ошибки

```bash
# Проверка шлюза
curl -v http://192.168.88.42:18087/health

# Проверка рендера независимо от веб-редактора
curl -v -H 'Content-Type: text/plain' \
  --data-binary @samples/sequence.mmd \
  http://192.168.88.42:18087/mermaid/svg \
  -o /tmp/test-kroki.svg

# Логи связанных контейнеров
sudo docker compose logs --tail=120 kroki kroki-mermaid mermaid-editor
```

Если POST успешен, но кнопка Mermaid ведёт не туда, проверьте **runtime-настройки редактора, версию образа и браузерный кэш**, а не в движке Kroki.

## Замечание об Ubuntu/UFW

Публикуемые Docker-порты взаимодействуют с правилами маршрутизации/iptables/nftables. Не считайте `ufw deny` достаточной гарантией ограничения доступа без проверки с другого хоста. В безопасном варианте режьте входящий доступ на маршрутизаторе/VPN и проверяйте Docker firewall. См. [[11 - Конфиденциальность и безопасность]].
