# Установка и первый запуск

## До начала

Предполагается, что Docker Engine и Compose уже работают в Ubuntu, у вас есть `sudo`, сеть позволяет скачать Docker-образы, включая GHCR. Кастомный Mermaid-пакет публичный: авторизация для скачивания не требуется. Входящий доступ по LAN к выбранным портам разрешён **только доверенным устройствам**.

1. Распакуйте каталог `SA-Docker-Obsidian` на Ubuntu и перейдите в него.
2. Посмотрите локальные IP: `ip -4 -brief address`.
3. Проверьте занятые порты: `sudo ss -lntp | grep -E ':(9443|1808[1-7])\b' || true`.
4. Если ранее были запущены эти инструменты, остановите старый Compose-проект (не все контейнеры сервера целиком).

## Шаг 1. Создать настройки

```bash
cd /путь/к/SA-Docker-Obsidian
cp -n .env.example .env
nano .env
```

По умолчанию `BIND_IP=192.168.88.42`. Адрес **обязательно** должен быть назначен сетевому интерфейсу именно этой Ubuntu-машины; иначе Docker выдаст ошибку bind. Изменить адрес и порты можно до первого запуска.

## Шаг 2. Развернуть основной набор

```bash
bash scripts/first-run.sh
```

Скрипт:

1. Проверяет Docker, Docker Compose, curl и адрес `BIND_IP`.
2. Проверяет конфигурацию Compose.
3. Скачивает готовые образы, включая кастомный Mermaid из GHCR.
4. Запускает компоненты `sa-analyst-suite` без сборки исходников.

Адрес Kroki передаётся Mermaid при запуске. При смене адреса пересборка не нужна. Версия редактора задаётся `MERMAID_IMAGE` в `.env`; полный `KROKI_URL` можно задать отдельно для HTTPS или DNS.

### Ручной эквивалент

```bash
sudo docker compose config --quiet
sudo docker compose pull
sudo docker compose up -d --no-build
```

## Шаг 3. Portainer (только если ещё не установлен)

**Сначала проверьте:**

```bash
sudo docker ps -a --format '{{.Names}}  {{.Image}}' | grep -i portainer || true
```

Если Portainer уже есть (в том числе от предыдущей установки), **не запускайте второй**. Если нет:

```bash
sudo docker compose -f compose.portainer.yaml up -d
```

Адрес `https://192.168.88.42:9443`. На первом входе нужно создать администратора, возможно ввести setup token из `sudo docker logs sa-portainer-portainer-1`. Точное имя контейнера можно узнать через `sudo docker compose -f compose.portainer.yaml ps`.

> [!warning] Безопасность Portainer
> Portainer имеет доступ к Docker socket с высокими полномочиями. Не открывайте `9443` в интернет; ограничьте доступ VPN/LAN и используйте сложный пароль. Сертификат по умолчанию самоподписанный.

## Шаг 4. Проверка

```bash
sudo docker compose ps
bash scripts/healthcheck.sh
```

Скрипт проверит HTTP-ответы и реально отправит тестовую Mermaid-диаграмму на **POST `/mermaid/svg`** Kroki. HTTP 200 для главной страницы не означает, что все функции исправны: проверьте также отдельные редакторы в браузере.

Проверьте открытие:

- Mermaid: `http://192.168.88.42:18081`
- PlantUML: `http://192.168.88.42:18082`
- Swagger Editor: `http://192.168.88.42:18083`
- Swagger UI: `http://192.168.88.42:18084`
- draw.io: `http://192.168.88.42:18085/?offline=1&https=0`
- AsyncAPI: `http://192.168.88.42:18086`
- Kroki: `http://192.168.88.42:18087`
- Portainer: `https://192.168.88.42:9443`

Если `BIND_IP` изменён — замените адрес в ссылках.

## Опциональный рендер Excalidraw

```bash
sudo docker compose --profile extras up -d
```

Companion `kroki-excalidraw` добавляется в Docker-сеть; его порт снаружи не публикуется. Это **API рендеринга**, не отдельный интерактивный редактор Excalidraw.

## Если уже использовали прошлый Docker-набор

В этом архиве имя Compose-проекта `sa-analyst-suite`; в прошлой инструкции могло быть другое. Если оба набора используют одинаковые внешние порты — запуск нового не завершится. Найдите владельцев портов через `sudo docker ps --format '{{.Names}} {{.Ports}}'` и завершите нужные **старые контейнеры**, не выполняя массовые `docker rm -f $(docker ps -aq)`.
