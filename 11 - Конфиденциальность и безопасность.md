# Конфиденциальность и безопасность

> [!danger] Ключевое ограничение
> Это **LAN-стенд инструментов аналитика**, а не сертифицированная платформа обработки защищённых данных. Обычные веб-редакторы здесь **не имеют собственной авторизации**. Проброс на `192.168.88.42` вместо `0.0.0.0` ограничивает сетевой интерфейс, но **не делает доступ персональным**: любой имеющий сетевую связность с этим интерфейсом может обратиться к портам (если ACL/firewall позволяет).

## Каналы утечки и меры контроля

| Продукт / механизм | Риск | В нашем Compose | Дополнительно для строгого режима |
|---|---|---|---|
| **Mermaid → mermaid.ink** | Экспорт по публичной ссылке может отправить исходник диаграммы во внешний сервис | `MERMAID_RENDERER_URL: ""` **при сборке**, публичная ссылка отключена | Проверять DevTools Network; ограничить исходящий трафик браузера |
| **Mermaid → kroki.io** | Внешний рендер получает схему | `KROKI_URL` задаёт **локальный** Kroki при запуске; runtime-файл загружается браузером | Убедиться, что ссылка действительно на `BIND_IP:18087`; протестировать на новой вкладке |
| **Mermaid — аналитика/Chart** | Внешние запросы аналитики и коммерческих ссылок | Параметры аналитики и Mermaid Chart отключены при сборке | Политика egress/CSP, проверка сторонних загрузок в DevTools |
| **Swagger UI — validator.swagger.io** | Внешняя проверка OpenAPI | `VALIDATOR_URL: none` | Сохранить при обновлении |
| **Swagger UI — Try it out** | Пользователь может отправить реальные API-запросы | `SUPPORTED_SUBMIT_METHODS: "[]"` | Ограничить HTTP доступ к backend на уровне сети и API |
| **PlantUML Server** | Диаграмма может пытаться читать локальные файлы и внешние URL | `PLANTUML_SECURITY_PROFILE: SANDBOX` | Сохранять; проверять поведение используемой версии |
| **Kroki** | Встроенные библиотеки могут делать include/запросы | `KROKI_SAFE_MODE: SECURE` | Запрет egress на firewall уровне; ограничение ресурсов и rate-limit через proxy |
| **Kroki URL-форма GET** | Закодированный исходник может попасть в историю/логи браузера и reverse proxy | Поддерживается API, отдельно не отключена | Для чувствительных схем использовать POST; ограничить доступ к логам |
| **draw.io offline mode** | Облачные хранилища или внешние assets | URL `?offline=1&https=0` в руководстве, не параметр контейнера | Проверить Network; при необходимости полностью изолировать от интернета |
| **Swagger Editor / AsyncAPI Studio** | Данные в памяти браузера и потенциальные внешние ссылки/зависимости | Самостоятельные локальные контейнеры | Экспортировать контракт, контролировать внешние вызовы клиента и сеть |
| **Portainer** | Через доступ к Docker socket можно управлять всеми контейнерами | HTTPS `9443`, пароль, volume | Не публиковать в интернет; VPN, ACL, ограничение пользователей |
| **Прочие HTTP редакторы** | Данные по сети могут перехватываться | HTTP в доверенной LAN | HTTPS reverse proxy + доверенный сертификат + авторизация |

## Что локально, а что может быть внешним

1. **Kroki:** рендер текста идёт в ваших Docker-контейнерах, но само по себе это не запрещает сетевые обращения серверов или браузера.
2. **Mermaid:** HTML/JS загружается локально, live preview строится в браузере; ссылка Kroki настроена на локальный сервер.
3. **Swagger и AsyncAPI:** в контейнерах живёт приложение, но рабочий документ обычно открыт **в браузере пользователя**; локальный контейнер не гарантирует, что браузер никогда не запросит внешний URL.
4. **Portainer:** доступ к нему по HTTPS, остальные UI без TLS в приведённой схеме.

## Рекомендуемые меры

1. **Не делайте** port-forward портов `9443` и `18081–18087` с роутера в интернет.
2. Разрешайте порты только нужным LAN/VPN-клиентам. Для Docker учитывайте, что опубликованные порты могут обходить ожидаемое поведение обычных правил UFW; используйте подходящие правила в Docker firewall/DOCKER-USER или внешнем маршрутизаторе, проверяя на практике.
3. Для корпоративных схем и персональных данных — TLS/SSO/reverse-proxy + разграничение доступа и отдельная оценка обработки данных. Доступ через IP по HTTP не соответствует требованиям для конфиденциальной сети без дополнительных мер.
4. В браузере проверьте **DevTools → Network**, нет ли обращений к публичным renderer, CDN и валидаторам.
5. Не помещайте секреты, токены, персональные данные в исходники, примеры, HTTP GET query и логи. Учитывайте, что `docker logs` тоже может содержать чувствительную информацию.
6. Закрепите теги/digest образов в контролируемой среде, обновляйте регулярно, проверяйте уязвимости образов.

## Отдельно о доступе к файлам

- `./specs:/specs:ro` — файловая папка Docker host, только чтение из Swagger UI.
- `portainer_data` — named volume. Его потеря означает потерю настроек Portainer.
- Редакторы не получают произвольного доступа к файлам вашей Ubuntu через bind mounts (кроме явно перечисленных). **Но** у Portainer есть Docker socket, который даёт ему возможность создавать контейнеры с дополнительными mounts.
