# PlantUML Server

**Назначение:** UML sequence/activity/class/deployment диаграммы из текстового PlantUML. Адрес по умолчанию: `http://192.168.88.42:18082`.

## В Docker

```yaml
plantuml:
  image: plantuml/plantuml-server:jetty
  restart: unless-stopped
  environment:
    PLANTUML_SECURITY_PROFILE: SANDBOX
  ports:
    - "${BIND_IP}:18082:8080"
```

`SANDBOX` запрещает обращения PlantUML к локальным файлам/внешним URL при генерации. Не отключайте этот профиль без отдельного анализа угроз.

## Как пользоваться

1. Откройте адрес сервера в браузере.
2. Вставьте пример из `samples/sequence.puml`.
3. Нажмите кнопку отображения/обновления рисунка (подписи зависят от версии интерфейса).
4. Сохраните **исходный `.puml`**, а изображение экспортируйте в SVG/PNG.

## Отличие от Kroki

| Вариант | Куда обращаться | Для чего |
|---|---|---|
| Отдельный PlantUML Server | `http://192.168.88.42:18082` | Интерактивная веб-страница и ссылки PlantUML. |
| PlantUML через Kroki | POST `http://192.168.88.42:18087/plantuml/svg` | Унифицированный API для скриптов и CI/CD. |

В Kroki уже есть PlantUML, поэтому **для автоматической генерации второй сервер не обязателен**. Но оставляем оба инструмента, поскольку по задаче нужны оба редактора/веб-варианта.

> [!important] Включение внешних библиотек
> При `SANDBOX` обычные `!includeurl https://...` не пройдут. Храните шаблоны локально и пересмотрите модель безопасности, если захотите разрешить специфичные ресурсы.

## Next AI PlantUML: какие языки поддерживаются

[Next AI PlantUML](https://github.com/mire403/Next-AI-PlantUML) — отдельное AI-приложение, а не наш `plantuml-server`. Проверка исходников: **27 октября 2026 года**.

- **Интерфейс:** преимущественно упрощённый китайский с английскими техническими названиями. Переключателя языка и файлов локализации в проверенном дереве нет. Русского и английского перевода интерфейса как отдельных режимов не найдено.
- **Запросы:** поле принимает произвольный текст и изображение. Можно написать запрос по-русски, однако качество понимания зависит от подключённой Gemini; это не отдельная проверенная поддержка русского языка.
- **Ответы:** системный промпт требует архитектурный анализ **на китайском**. Подписи и примечания диаграммы тоже китайские по умолчанию, но для них есть оговорка «unless specified otherwise»: явно просите русские подписи. Промпт визуального ревью также требует китайский.
- **Язык диаграмм:** генерируется PlantUML (`@startuml`/`@enduml`, `actor`, `class` и т. д.); русские названия элементов можно писать в кавычках. Это не перечень поддерживаемых языков программирования и не отдельный парсер исходников Java/Python/C#.

Пример запроса: «Создай диаграмму последовательности оформления заказа. Все подписи участников и сообщений сделай на русском языке». Чтобы перевести также анализ и ревью, надо изменить `SYSTEM_INSTRUCTION` и `REVIEW_INSTRUCTION` в `services/gemini.ts`; для полного перевода — строки в `App.tsx` и `components/*.tsx`.

В текущем коде подключена Gemini, а Ollama/DeepSeek в README отмечены как планы. `services/plantuml.ts` отправляет код на публичный `www.plantuml.com`; для локальной обработки его надо переключить на наш PlantUML/Kroki. В Compose этот проект не добавлен.
