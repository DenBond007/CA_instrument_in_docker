# draw.io / diagrams.net

**Назначение:** визуальное моделирование процессов, компонентов, C4-подобных схем, контекстов интеграции и инфраструктуры без необходимости писать код.

## Адрес

**Рекомендуемый для локальной работы:**

`http://192.168.88.42:18085/?offline=1&https=0`

При использовании `http://` для `jgraph/drawio` официальный README рекомендует параметры `offline=1&https=0`.

## Compose

```yaml
drawio:
  image: jgraph/drawio:latest
  restart: unless-stopped
  ports:
    - "${BIND_IP}:${DRAWIO_PORT:-18085}:8080"
```

## Как пользоваться

1. Откройте URL и выберите создание диаграммы.
2. Откройте редактор и нарисуйте схему: роли, компоненты, связи, шины, потоки данных.
3. При сохранении выбирайте **Device/устройство** или локальное хранение, а не облачное.
4. Сохраняйте редактируемый файл `.drawio` и экспортированный `.svg` / `.png`. Исходники версий держите в Git.
5. Для подготовки раздела архитектуры помещайте `.drawio` и иллюстрацию рядом с текстом в Obsidian.

## Ограничения и конфиденциальность

- `offline=1` отключает интеграции с облачными хранилищами **в рамках приложения**, но **не доказывает** полное отсутствие всех внешних HTTP-запросов. При повышенных требованиях проверьте Network браузера и egress-политику.
- Сохранение на Device означает сохранение **через браузер/на выбранный диск**, не в Docker volume.
- У draw.io **нет штатной интеграции** с нашим Kroki для интерактивного редактирования. Можно импортировать SVG/PNG, созданные Kroki; это уже растровый/векторный результат, а не гарантированно редактируемая диаграмма draw.io.
- Kroki имеет **экспериментальный** companion `kroki-diagramsnet`, но он не нужен для обычной работы draw.io и **не включён** в наш Compose.
