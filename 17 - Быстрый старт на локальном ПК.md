# Быстрый старт на локальном ПК

Docker Desktop уже установлен и запущен. Здесь инструменты доступны **только с этого ПК**, через `127.0.0.1`; IP локальной сети узнавать не нужно. Если установлен только Kubernetes, переходите к [[18 - Быстрый старт в локальном Kubernetes]]: Docker CLI и Compose для того варианта не требуются.

| Система | Где выполнять команды Docker | Подготовка |
|---|---|---|
| Ubuntu | Обычный терминал пользователя | Раздел «Ubuntu» ниже |
| Windows | Ubuntu в WSL 2 с интеграцией Docker Desktop | Раздел «Windows» ниже |
| macOS, Intel или Apple Silicon | Terminal | Раздел «macOS» ниже |

Нужны Git, Python 3 и curl, доступ к реестрам Docker Hub, GHCR и `docker.swagger.io`. Для загрузки публичных образов этого проекта токен GitHub не нужен. Практический ориентир для всего набора — 4 CPU и 8 ГиБ памяти, выделенных контейнерной среде; это рекомендация для старта, а не измеренный минимум. LLM в эти ресурсы не включена и для первого запуска не нужна.

## Ubuntu

Запустите Docker Desktop. В обычном терминале:

```bash
docker context ls
docker context use desktop-linux
docker info --format '{{.OSType}}'
docker compose version
git --version
python3 --version
curl --version
```

Ожидается `linux` и доступный Compose. Если недостаёт утилит:

```bash
sudo apt-get update
sudo apt-get install -y git python3 curl
```

Далее выполняйте общий запуск ниже. Команды Docker запускайте **без sudo**, чтобы использовать пользовательский контекст Docker Desktop. Штатные `first-run.sh` и `update.sh` рассчитаны на Ubuntu с системным Docker Engine и используют `sudo`; их серверный сценарий описан в [[02 - Установка и первый запуск]]. Различие контекстов описано в [документации Docker Desktop для Linux](https://docs.docker.com/desktop/setup/install/linux/).

## Windows

Этот путь использует Docker Desktop с Linux-контейнерами и Ubuntu в WSL 2. Python-генератор проекта проверяет Unix-права файлов, поэтому команды общего запуска выполняются в WSL, а не в PowerShell или Git Bash.

В PowerShell проверьте установленный дистрибутив:

```powershell
wsl --list --verbose
```

Если Ubuntu отсутствует, установите её из PowerShell с правами администратора, завершите первоначальную настройку пользователя и при необходимости перезагрузитесь:

```powershell
wsl --install -d Ubuntu
```

Если в списке для Ubuntu указана версия `1`, выполните `wsl --set-version Ubuntu 2`. В Docker Desktop включите **Use WSL 2 based engine** и **Settings → Resources → WSL Integration → Ubuntu**, примените настройки. Если используется режим Windows containers, переключитесь на **Linux containers**. Эти настройки описаны в [официальной инструкции Docker для WSL](https://docs.docker.com/desktop/features/wsl/).

Откройте Ubuntu:

```powershell
wsl -d Ubuntu
```

Теперь **в терминале Ubuntu WSL**:

```bash
sudo apt-get update
sudo apt-get install -y git python3 curl
docker context ls
docker info --format '{{.OSType}}'
docker compose version
```

Ожидается `linux`. Контекст `desktop-linux` в WSL выбирать не нужно: подключение предоставляет интеграция Docker Desktop. Дополнительный Docker Engine внутри Ubuntu не устанавливайте. Общий запуск ниже создаст проект в Linux-каталоге `~/Projects`; браузер открывайте в Windows по `http://127.0.0.1:18080`. Хранение исходников внутри дистрибутива соответствует [рекомендациям Docker для WSL](https://docs.docker.com/desktop/features/wsl/use-wsl/).

## macOS

Запустите Docker Desktop и откройте Terminal:

```bash
docker context ls
docker info --format '{{.OSType}}'
docker compose version
git --version
python3 --version
curl --version
```

Ожидается `linux`. Если CLI направлен в другой Docker, выберите контекст Docker Desktop из вывода `docker context ls`. Для отсутствующих Git/Python установите их привычным способом; при уже установленном Homebrew можно выполнить `brew install git python`. Команды запуска ниже одинаковы на Intel и Apple Silicon; ограничения отдельных образов рассмотрены в диагностике.

Проект в `~/Projects` обычно попадает в доступную Docker область `/Users`. При ошибке `Mounts denied` разрешите этот каталог в **Settings → Resources → File sharing**. См. [настройки Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

## Общий запуск: Ubuntu, Windows WSL и macOS

Все блоки этого раздела выполняйте по порядку в терминале, выбранном для вашей ОС. При ошибке остановитесь и исправьте её до следующего шага.

### 1. Скачать проект

```bash
mkdir -p ~/Projects
cd ~/Projects
git clone https://github.com/DenBond007/CA_instrument_in_docker.git
cd CA_instrument_in_docker
```

Если проект уже скачан, перейдите в его корень с `compose.yaml`; повторное клонирование не нужно. Не запускайте второй экземпляр набора на тех же портах.

### 2. Задать локальные настройки без LLM

```bash
test -f .env || cp .env.example .env
```

Откройте `.env` в текстовом редакторе. **Замените** значения перечисленных переменных; отсутствующие добавьте один раз:

```dotenv
BIND_IP=127.0.0.1
PORTAL_HOST=127.0.0.1
PORTAL_IMAGE=local/analyst-portal:dev
PORTAL_SHOW_PORTAINER=false
DRAWIO_AI_ENABLED=false
```

Остальные значения оставьте из `.env.example`, в том числе порты `18080`–`18088`. При первом запуске `AI_DRAWIO_MODEL` и `AI_DRAWIO_API_KEY` могут быть пустыми. Оба редактора draw.io откроются, но генерация схем через модель ещё не настроена. `.env` и создаваемая `.local/` исключены из Git.

### 3. Подготовить настройки, собрать портал и запустить

```bash
chmod 600 .env
docker compose config --quiet
python3 scripts/prepare-drawio-ai.py
docker compose -f compose.yaml -f compose.build.yaml build portal
docker compose pull kroki kroki-mermaid kroki-bpmn mermaid-editor plantuml swagger-editor swagger-ui drawio drawio-gateway ai-drawio asyncapi
docker compose up -d --no-build --force-recreate
docker compose ps
```

Сборка нужна только небольшому порталу: опубликованный `analyst-portal:1.0.0` ещё не содержит карточку Next AI Draw.io. Остальные образы скачиваются готовыми, Mermaid локально не собирается. Портал и Mermaid считывают адрес Kroki при запуске; публичный рендерер вместо локального не включается.

`--force-recreate` также подключает заново сгенерированные файлы draw.io. При повторении команды активные контейнеры **этого** Compose-проекта будут пересозданы; сохраните работу в браузере заранее.

### 4. Проверить и открыть

Первая загрузка и прогрев Java-сервисов могут занять несколько минут. Проверка HTTP и реального рендера Mermaid:

```bash
for port in 18080 18081 18082 18083 18084 18085 18086 18087 18088; do
  curl -fLsS --retry 20 --retry-connrefused --retry-delay 3 --max-time 10 -o /dev/null "http://127.0.0.1:${port}/" || break
done
curl -fsS --max-time 45 -H 'Content-Type: text/plain; charset=utf-8' --data-binary @samples/sequence.mmd http://127.0.0.1:18087/mermaid/svg -o /tmp/analyst-kroki-check.svg
grep -q '<svg' /tmp/analyst-kroki-check.svg && echo 'Kroki: SVG получен'
```

Откройте **[портал инструментов](http://127.0.0.1:18080)**. Прямые адреса:

| Инструмент | Адрес |
|---|---|
| Mermaid Live Editor | http://127.0.0.1:18081 |
| PlantUML Server | http://127.0.0.1:18082 |
| Swagger Editor | http://127.0.0.1:18083 |
| Swagger UI с `specs/openapi.yaml` | http://127.0.0.1:18084 |
| draw.io без AI | http://127.0.0.1:18085/?offline=1&https=0&mode=device |
| AsyncAPI Studio | http://127.0.0.1:18086 |
| Kroki API | http://127.0.0.1:18087 |
| Next AI Draw.io, генерация после настройки модели | http://127.0.0.1:18088 |

Создайте простую схему и сохраните исходник на ПК. Успешный HTTP-ответ не проверяет все функции редактора. `scripts/healthcheck.sh` подходит для Ubuntu/WSL; приведённый выше блок переносим и на macOS, где отличается `mktemp`.

## Остановка, повторный запуск и обновление

В корне проекта, в том же Docker-контексте:

```bash
docker compose stop
docker compose start
```

Это две отдельные операции: первая останавливает набор, вторая запускает его снова. Для удаления контейнеров и сети только этого набора выполните `docker compose down`. Не добавляйте `-v`, если нужны серверные настройки Next AI Draw.io в volume. Схемы `.drawio`, `.mmd`, `.puml` и контракты сохраняйте отдельно.

Перед обновлением сохраните `.env`, `.local/drawio` и рабочие файлы в закрытом месте. Получите изменения исходников после сохранения своих правок, затем повторите шаг 3: он скачает образы, пересоберёт портал и пересоздаст контейнеры. Ubuntu-скрипт `update.sh` в Desktop-сценарии не нужен.

## Подключение модели и Portainer

Для AI задайте подключение в `.env` по [[08 - draw.io]] и [[16 - Next AI Draw.io]], затем включите `DRAWIO_AI_ENABLED=true`, выполните генератор и пересоздайте `drawio`, `drawio-gateway`, `ai-drawio`, `portal`. В Docker Desktop адрес модели на хосте — `host.docker.internal`, а не `127.0.0.1` контейнера. На Windows учитывайте, запущен сервер модели в Windows или внутри WSL. Установка и загрузка модели выполняются отдельно.

Portainer необязателен. Если его ещё нет, при работающем Docker Desktop можно запустить `docker compose -f compose.portainer.yaml up -d`, открыть `https://127.0.0.1:9443` и создать администратора; сертификат по умолчанию самоподписанный. Для карточки портала задайте `PORTAL_SHOW_PORTAINER=true` и пересоздайте портал. Подробности — [[09 - Portainer - инструкция со скриншотами]].

## Если запуск не удался

| Симптом | Действие |
|---|---|
| Docker daemon недоступен | Запустите Docker Desktop; проверьте `docker context ls`, в WSL — интеграцию Ubuntu |
| `Задайте DRAWIO_AI_MODEL...` | Для старта без модели укажите `DRAWIO_AI_ENABLED=false` и повторите генератор |
| `bind: cannot assign requested address` | Укажите `BIND_IP=127.0.0.1`, уберите оставшийся пример LAN IP |
| `port is already allocated` | Остановите прежний экземпляр набора либо измените соответствующий порт в `.env` и используйте его при проверке |
| Не найден локальный образ портала | Выполните сборку `portal` из шага 3; локальный тег из реестра не скачивается |
| Ошибка bind mount draw.io | Выполните генератор до `up`; в macOS проверьте File sharing, в Windows используйте каталог WSL |
| `no matching manifest for linux/arm64` | У конкретного стороннего образа нет ARM64-варианта; выберите поддерживаемый тег либо настройте AMD64-эмуляцию Docker Desktop и `platform: linux/amd64` только для этого сервиса в отдельном Compose override |
| HTTP ещё недоступен | `docker compose ps`, затем `docker compose logs --tail=100 ИМЯ_СЕРВИСА` |

Меняя порт в `.env`, обновляйте также команды проверки. Для доступа из LAN/VPN вместо локального сценария используйте [[02 - Установка и первый запуск]] и [[11 - Конфиденциальность и безопасность]].

Границы проверки этих инструкций — [[14 - Источники и ограничения]].
